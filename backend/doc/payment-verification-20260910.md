订单金额、期限由服务端决定；客户端不能指定已付款状态或会员等级。身份验证复用既有 JWT。签名通知和主动查单均核对金额与订单，重复处理不重复累计期限。全额退款终态不会被旧成功通知覆盖。超过 5 分钟的有效付款缓存会再次查单，失败返回错误而不伪称已重新核验。唯一索引在支付启用时完成初始化后才开放监听。

账号删除先阻止新购买，清理用户关联及客户端幂等键；付款通知不会复活已删除账号。同一手机号重新注册无法接管旧付款。保留最小商户流水以核对迟到退款；正式上线仍需确定财务记录保留期限。

## 继续真实联调

1. 用户启用沙箱公钥模式，将应用私钥、支付宝公钥保存到本地，保持密钥不进入聊天和 Git。
2. 配置独立沙箱环境文件，使用 `npm run payment:check-sandbox -- --env-file /absolute/path/to/sandbox.env`。检查工具只调用 `alipay.trade.query`；获得已验签的“订单不存在”可证明网关鉴权与响应验证，不能证明支付到账。
3. 配置实际可达的 HTTPS 通知地址。生成 APP `orderString` 是本地签名，只有客户端交给支付宝 SDK 后才向支付宝发起交易。
4. 使用 Android 沙箱客户端完成付款、查单、真实回调及退款测试。当前 iOS 没有沙箱钱包，iOS 真机交易需正式产品权限及单独确认的测试付款。

来源：[支付宝 APP 集成指南](https://aipay.alipay.com/docs/vibe-pay/mobile-app-pay/app-pay-integration-guide-new.html)、[退款通知字段](https://aipay.alipay.com/docs/vibe-pay/mobile-app-pay/ai-app-pay/async-notify-verify.html)、[iOS 沙箱限制](https://global.alipay.com/developer/helpcenter/detail?_route=sg&categoryId=50477&knowId=201602452726&sceneCode=AC_DEV)。

## 依赖与发布边界

本次新增官方 `alipay-sdk@4.14.0` 并更新其与现有依赖共享的 `qs` 至 6.16.0。额外查证 npm 的 `latest-4` 标签后，将 SDK 间接依赖 `urllib` 固定到已修复重定向头泄露的 4.9.1；默认 `latest` 标签仍为 4.9.0，因此普通更新没有取得补丁。补丁后 34 项 SDK、配置、运行时单测通过，语法及差异检查通过。`npm audit --omit=dev` 现在只剩既有 `multer@2.2.0` 的高危项，不属于新增支付依赖；发布前仍须处理该上传模块依赖。本次未部署生产。

磁盘空间阻塞已于 2026-09-11 解除。补跑前 `df -h .` 显示可用空间 18 GiB；此前约 300 MB 空间低于 MongoDB 建索引最低 500 MB 的限制，本次未再出现。未降低数据库安全阈值。`npm run check` 与 `npm test -- --silent` 均退出码 0，最终回归为 22 个套件通过、1 个跳过，201 项测试通过、1 项跳过，耗时 25.985 秒；支付业务与注销建单竞态集成测试均实际进入执行并通过。

本次补跑只验证本地代码、真实 loopback HTTP、临时 MongoDB 及本地 RSA 签名验签。真实支付宝沙箱密钥仍待用户启用并提供本地文件路径，尚未请求真实支付宝网关，未完成真实付款、回调或退款测试；生成本地 APP `orderString` 不代表支付宝已创建订单或收到付款。未启动或修改云端服务，未占用 5001 端口，未部署生产。

中国大陆 App Store 数字会员的支付分发仍需满足 Apple 当前审核规则。支付宝个人 AI 收款可接入资格与 App Store 分发规则是两件事，不能互相替代；Apple 路线继续保留在 [接口文档](payment-api-20260910.md) 中。
